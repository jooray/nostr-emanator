## Design Specificity Verdict

Not slop at the surface: no emoji-as-icons, no gradients outside the landing page, no "seamless/effortless/unlock", exactly one exclamation mark in the app (and it's in the wrong place — "Signing complete!"). The copy is not the vector. The structure and styling layer are.

- `app/assets/stylesheets/application.tailwind.css` last touched 2026-02-13 (day 3). Defines 12 tokens; **no view uses one**. They feed an `!important` layer repainting stock Tailwind (`.dark .bg-gray-800 { ... !important }` × 30).
- Line 5 comment says "Solarized-inspired"; palette is `#0a0a0a/#141414/#1c1c1c` neutral grayscale. Factually false comment at the top of the design layer.
- Lines 83–105 remap `purple-*` → amber, dark-mode only: fossil of a generated Tailwind demo accent recoloured by override. `CalendarController::CHIP_CLASSES` still leads with purple.
- `dashboard/index.html.erb:11–93` is Tailwind UI "Stats with card footer" pasted 4× verbatim (`ml-5 w-0 flex-1` tell).
- 52 card shells in 13 spellings. `view_component` in Gemfile; `app/components/` does not exist.
- `shared/_avatar.html.erb` re-inlined by hand in 7 places at 4 sizes, amber fallback in 4 / gray in 2 — both visible in schedule-mobile-dark.png.

Landing vs app: `home/index.html.erb` = 24 semantic tokens × 2 themes, warm-paper light palette, Inter, skip link, `lang="en"`, 33 ARIA attributes. App = 12 tokens unused, `bg-gray-50`, no typeface declared, no skip link, no `lang`, 8 hand-written ARIA attributes.

**Deterministic scan:** 15 findings, **1 real** (`overused-font`, Inter, landing page). 13 `gray-on-color` are Tailwind `hover:`/`dark:` modifier and Ruby ternary-branch confusion; 1 `broken-image` matched an `<img>` inside an ERB comment. Mechanical a11y sweep: 0 unlabeled images, 0 inline `onclick`, 0 positive `tabindex` (CSP-nonce discipline is clean); 10 back-links with no accessible name, 5 unlabeled inputs, 14 icon-only controls.
**Tooling note:** `impeccable detect --json app/views` returns exit 0 / zero findings — directory mode silently skips `.html.erb`. Real scan needs an explicit file list.
**Visual overlays: none.** No injection (Nostr-only auth, dev server deliberately not started); landing-page fallback also failed (Chrome extension not connected). Visual judgment came from `public/landing/shots/` (13 captures, dated 2026-07-16 — stale: Messages shipped 2026-07-30, so the public landing page markets a build with a 6-item sidebar while the app ships 7).

## What's Working

1. `conversations/_composer_body.html.erb` — four delivery states each mapped to a consequence; `:checking` refused the downgrade offer; "Send with public metadata" instead of "Send"; risks from a model constant; `turbo_permanent` so an arriving message can't wipe a half-typed reply.

## Priority Issues

### [P0] "Published" is not true — partial relay delivery renders as unqualified success
1/6 relays sets `post.published?` → green border, green check, "Published"; `1/6 relays succeeded` sits under it in 12px gray at 2.85:1. Same green badge for `scheduled` and `published` across posts list, dashboard, reposts list. Violates Principle 4. No failure notification of any kind (Messages gets a nav badge; failures don't), despite being an installed PWA. Failed card is ~3 mobile screens down and shows neither reason nor retry.
**Fix:** delivery grade from `publish_results` (`all`/`partial`/`none`), count in the badge, partial in amber; put "did anything break?" where "Total Posts" is; nav badge; reason + inline retry on the failed row.
**Files:** `posts/_publish_progress.html.erb:2–45`, `posts/index.html.erb:19–27`, `posts/show.html.erb:2–10`, `posts/_reposts_list.html.erb:30–47`, `dashboard/index.html.erb:11–93,146,157–173`
**Command:** `/impeccable harden`

### [P0] The 120-second signer wait is a pulsing icon and a percentage
No duration expectation, no account name (of 19), no approval count (`total_items` is computed then used only for a percentage), no "safe to close this tab", one generic sentence for four distinct failure causes. `blossom_upload_controller.js` already counts ("1 of 2") — the lower-stakes flow does it better. Five different phrasings of the same wait across the app.
**Fix:** enumerated queue (one row per event, naming its account, ✓/spinner/✗), elapsed + expectation, "you can close this tab", name Amber, split the four causes and link permissions drift to `re_pair_account_path(reason:)`.
**Files:** `posts/_signing_progress.html.erb:10,34,49–77` + `inline_reply_controller.js:145`, `interaction_actions_controller.js:210`, `blossom_upload_controller.js`, `_composer_body.html.erb`
**Command:** `/impeccable clarify`

### [P1] The styling layer is the day-three scaffold — the actual source of the slop read
Also causes live bugs: flatpickr blue/amber split, two avatar systems, active-nav `#1c1c1c` on `#141414` (~3% delta, no `aria-current`, no rail).
**Fix:** lift `home/index.html.erb:14–56` tokens into the app (surface/line/ink/muted/amber + 3-state theme + warm-paper light), declare a typeface, one `CardComponent` with variants, delete the `!important` block and the hand-rolled `.line-clamp-*`, fix the false Solarized comment, `aria-current` + 2px amber rail on nav.
**Files:** `app/assets/stylesheets/application.tailwind.css`, `layouts/application.html.erb`, `layouts/_navigation.html.erb`
**Command:** `/impeccable extract`

### [P1] Nineteen accounts break every multi-account surface
18 unfiltered checkboxes + Select All arming 18 signatures with no count; `ACCOUNT_COLOR_NAMES[i % 7]` collides at #1/#8/#15, reshuffles on pairing, no legend; interactions pills render N+1 all-amber regardless of state and don't survive reload. Violates Principle 5.
**Fix:** one stable visual atom per account derived from `pubkey_hex` used on every surface + legend; reuse `select_account`'s filter on the repost picker; "Repost to 18 accounts — 19 signer approvals".
**Files:** `calendar_controller.rb:9–86`, `calendar/index.html.erb:38–54`, `posts/schedule.html.erb:82–136`, `interactions/index.html.erb:12–31`
**Command:** `/impeccable shape`

### [P1] Accessibility floor — a real keyboard trap, and silent state transitions
`mobile_nav_controller.js` toggles `-translate-x-full` only: 7 links + Sign out stay tabbable while off-screen, focus never moved in or restored, no `aria-expanded`. Zero `aria-live` anywhere — signing, publishing, liking, following, uploading all write `.textContent` into plain spans and self-clear after 3s. 10 back-chevrons with no accessible name; theme toggles have only `title` (the landing page's has `aria-label`). No `lang`, no skip link. `text-gray-400` on white (2.85:1) carries the delivery evidence.
**Fix:** `lang` + skip link copied from the landing page; `inert` + focus management on the mobile panel; `role="status"` on progress + flashes; `aria-label` on the 10 back links and icon-only controls; lift delivery text off gray-400.
**Command:** `/impeccable audit`

## Persona Red Flags

**Riley (stress):** 0 accounts → dashboard opens on 0/0/0/0 above the Get Started card; 0 interactions → 5 skeleton cards forever if `FetchInteractionsJob` never broadcasts (no timeout, no error path); unnamed accounts all render "N"; dashboard pill has no truncate so a 63-char npub destroys the row; a day with 8 posts shows 5 and a dead "+3 more"; `+ 1 reposts` hardcoded plural (visible in the shipped screenshot) while `posts/index` pluralizes correctly.
